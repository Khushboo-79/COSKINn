 COSKINn Fruit-Powered Skincare &amp; Makeup PRODUCT REQUIREMENTS DOCUMENT PRD v1.0 Web: React + Tailwind CSS | App: React Native | Backend: Node.js + PostgreSQL on AWS Payments: Razorpay | Delivery Partner: ShadowFox July 2026 1. Purpose &amp; Vision COSKINn is a premium, Gen-Z-friendly, fruit-powered skincare and makeup ecommerce brand, launching as an inventory-led / private-label business with a limited, curated product range (12 skincare + 12 makeup SKUs at launch). This PRD defines what must be built for the first production launch: a customer website (React + Tailwind CSS), a customer mobile app (React Native), and a Node.js/PostgreSQL backend on AWS — including a full customer loyalty and monetary ecosystem (Wallet, Bonus, Referral, Reward Points, Offers, and a tiered Membership program) alongside the operational back-office needed to run the business. 1.1 Problem Statement Indian beauty ecommerce is dominated by large multi-brand marketplaces. There is room for a tightly curated, ingredient-story-driven (fruit + skin concern), soft-luxury brand that gives customers a simple, trustworthy, habit-forming shopping experience — with the kind of loyalty mechanics (points, wallet, tiers) that keep shoppers of category leaders like Nykaa coming back. 1.2 Product Vision Become the go-to destination for fruit-based, concern-driven skincare and SPF-safe makeup for value-conscious Gen-Z/young-millennial shoppers in India, with a loyalty program compelling enough to drive repeat purchase from order one. 2. Target Users &amp; Personas Persona Profile Primary Need The Glow Seeker 18–28, college/early career, Instagram-active Affordable, cute, effective skincare with visible fruit-ingredient story The Routine Builder 22–32, skin-concern aware Guided routine (skin quiz) + trust signals (batch/expiry, dermat-tested) The SPF-Makeup Shopper 20–30, wants makeup with sun protection SPF lipstick/sunscreen-makeup crossover products The Loyal Repeat Buyer Any age, price + rewards sensitive Wallet cashback, reward points, membership perks, referral earnings 3. Functional Requirements — Core Shopping 4.1 Discovery &amp; Browsing ID Requirement Acceptance Criteria FR-1 Customer can browse by category, fruit ingredient, or skin concern Category, fruit, and concern filters each return correct product sets FR-2 Customer can search products by name/keyword Search returns relevant results in &lt;1s for typo-free queries FR-3 Customer can filter &amp; sort listings Filters (price, skin type, concern, fruit) and sort (price, rating, new) combine correctly FR-4 Product detail page shows ingredients, benefits, how-to-use, shade/variant selector, reviews All fields populate from Product Management panel data 4.2 Cart, Checkout &amp; Payment ID Requirement Acceptance Criteria FR-5 Customer can add/update/remove cart items across sessions and devices Cart persists per logged-in user FR-6 Customer can apply one coupon, wallet balance, and reward points together at checkout, subject to stacking rules System computes final payable amount correctly per configured stacking rules FR-7 Customer can pay via Razorpay (UPI/card/netbanking/wallet/EMI) or COD Payment success updates order status only after server-side signature/webhook verification FR-8 Customer receives order confirmation and tax invoice Invoice PDF generated with correct GST/HSN breakup 4.3 Orders, Tracking, Returns ID Requirement Acceptance Criteria FR-9 Customer can track order status end-to-end via ShadowFox tracking Status updates reflect ShadowFox webhook events within 5 minutes FR-10 Customer can request return/refund with reason + photo/video proof Return request routes to Admin/Support for approval within defined SLA FR-11 Refund is issued to original payment method or Wallet per policy Refund status visible to customer; reconciled against Razorpay Refunds API 5. Functional Requirements — Loyalty &amp; Monetary Ecosystem These sections are additive to the customer panel (app + web), as explicitly requested, and mirror the mechanics used by category-leading beauty apps (e.g. Nykaa Prive), rebuilt under COSKINn&apos;s own branding and rules. 5.1 Wallet ID Requirement Acceptance Criteria FR-W1 System maintains one wallet balance per customer Balance always equals sum of non-expired ledger entries FR-W2 Wallet is credited automatically from refunds, bonuses, referral payouts, and reward-point-to-wallet conversions Each credit is logged with source and reference ID FR-W3 Customer can apply wallet balance at checkout, partially or fully Wallet deduction cannot exceed available balance or order value FR-W4 Wallet credits expire per admin-configured policy Expired credits are excluded from usable balance automatically FR-W5 Customer cannot add money to wallet directly No &quot;add funds&quot; entry point exists anywhere in app/web 5.2 Bonus ID Requirement Acceptance Criteria FR-B1 New customers receive a sign-up bonus on registration Bonus credited to Wallet immediately after OTP verification, per admin rule FR-B2 Customers receive a first-order bonus post-delivery Bonus credited after the return window closes on the first order FR-B3 Customers receive a birthday bonus in their birth month Triggered by a scheduled job; tier-aware multiplier applied FR-B4 Admin can configure campaign-specific bonuses Marketing panel supports creating time-bound bonus rules 5.3 Referral ID Requirement Acceptance Criteria FR-R1 Every customer has a unique, shareable referral code/link Code generated on first login; shareable via native share sheet FR-R2 Referee gets a welcome discount on first order via referral code Discount auto-applies when code is used at signup/checkout FR-R3 Referrer is rewarded once referee&apos;s first order is delivered and past return window Reward (wallet credit or points) posts automatically; visible in referral dashboard FR-R4 System prevents duplicate/fraudulent referral claims One credited referral per unique verified mobile number/device; minimum order-value threshold enforced 5.4 Reward Points ID Requirement Acceptance Criteria FR-P1 Customer earns 1 reward point per ₹1 of eligible spend Points credited after return window closes on the qualifying order FR-P2 Points are redeemable at checkout up to an admin-configured cap Redemption cannot exceed max % of order value FR-P3 Points multiply during the customer&apos;s birthday month per tier Member 1.5x / Gold 2x / Platinum 3x applied automatically FR-P4 Points may be locked from redemption during designated sale windows Admin toggle disables point redemption during flagged campaigns FR-P5 Points expire per admin-configured policy Expired points are removed from the redeemable balance 5.5 Offers ID Requirement Acceptance Criteria FR-O1 Admin can create offers scoped to category, product, payment method, or membership tier Offer engine evaluates eligibility correctly at cart/checkout time FR-O2 Homepage displays an active Offers/Deals section Section reflects only currently valid (in date-range) offers FR-O3 Best eligible coupon/offer can auto-apply at cart System selects the highest-value valid offer when multiple qualify, unless customer overrides 6.
